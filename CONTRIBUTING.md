# Contributing to Coniungo Commons

Coniungo Commons is the open-source collective of [Coniungo Labs](https://coniungolabs.com). These are the starter templates and components we use in our own products, shared for anyone to read, use and improve. You don't need to work at Coniungo to have a say.

This guide applies to every public repo in [coniungo-repo](https://github.com/coniungo-repo) that doesn't have its own.

## From first issue to merged, in four steps

1. **Find an issue.** Look for issues labelled `good first issue` in any project, or open one for a bug you've hit.
2. **Say you're on it.** Comment on the issue so nobody doubles up, and so we can point you the right way early.
3. **Open a pull request.** Keep it small. Say what changed and why, and link the issue it closes.
4. **Get it reviewed.** A maintainer reviews it with you. Once it's merged, you're credited in the release notes.

## Reporting a bug

Open an issue in the project's repo and tell us:

- what broke,
- what you expected to happen,
- how to make it happen again (steps, versions, a small example if you can).

## Improving the docs

Docs changes are as welcome as code. Fix a confusing readme or add the example you wish had been there, and open a pull request the same way.

## Questions and ideas

Ask questions, suggest a starter we should build, or share what you've made in [Discussions](https://github.com/coniungo-repo/.github/discussions).
